# Roadmap

Tracked in GitHub issue #1 (one sub-issue per phase). Phases are mostly sequential; a
phase closes when its exit criterion is measured and recorded in
[progress](progress.md). Tasks may be added as development progresses.

## P0 — Bootstrap
- [ ] Repo skeleton, design, roadmap, workflow skill, CI (CPU tests), Python env.

## P1 — ROCm runtime and toolchain
- [ ] `agc/arch/gfx950.yaml` resources with source tags; model loader; occupancy calculator.
- [ ] `agc/runtime/hip.py`: HIP module API via ctypes (`hipModuleLoadData`, `hipModuleLaunchKernel`, memory, events, `hipFuncGetAttribute`).
- [ ] `agc/runtime/toolchain.py`: amdclang HIP builds (`.hsaco` and `-S`), `llvm-mc`, `ld.lld`, `llvm-objdump`; toolchain identity in cache keys.
- [ ] `agc/manifest.py` + `agc/dtypes.py` (ported; arch `gfx950`, bf16/fp16/fp8 storage).
- [ ] Executor: machine-wide lock, subprocess workers, device selection, accounting.
- [ ] Inputs, reference evaluation (NumPy; torch when present), battery check with error-model tolerances and output poisoning.
- [ ] Timing protocol `agc-timing-amd-1` with L2+MALL flush, CI-converged medians, paired comparison.
- [ ] CLI: `agc build|check|bench` on a manifest's amdclang build.

Exit: AXPY manifest builds with amdclang, passes the battery and times reproducibly.

## P2 — HIP corpus and baselines
- [ ] HIP corpus in `tests/kernels/` (elementwise, rowwise, reductions, softmax, norms, transpose, GEMM naive/tiled, matvec, …) with manifests and references.
- [ ] amdclang baseline file `tests/baselines/amdclang-gfx950.json` (timing + resources).

Exit: every corpus kernel builds, passes the battery and has a recorded baseline.

## P3 — ISA table and `mir` core
- [ ] `scripts/gen_isa.py`: CDNA4 XML → `agc/isa/cdna4.json.gz`; `agc/isa` query API.
- [ ] `agc/mir`: IR, text parser/printer for amdclang-dialect assembly, operands, blocks.
- [ ] Kernel descriptor and metadata model; register counts and `accum_offset` recomputed.
- [ ] Emit: `.s` → `llvm-mc` → `ld.lld` → `.hsaco`; import of amdclang asm.
- [ ] Round-trip: import → emit is byte-identical in `.text` for every corpus kernel; `llvm-objdump` cross-check.
- [ ] Verifier against the ISA table.

Exit: every corpus kernel imports, re-emits identically, verifies and passes the battery.

## P4 — Static safety: CFG, hazards, waitcnt, interpreter
- [ ] CFG, liveness, register def/use from the ISA table.
- [ ] Waitcnt checker (counter dataflow: vmcnt/lgkmcnt/expcnt, in-order and out-of-order classes).
- [ ] Hazard checker (wait-state table in arch data: VALU→SGPR→VMEM, MFMA dependencies, trans ops, exec writes, …).
- [ ] Zero violations on all corpus amdclang outputs; seeded mutations caught.
- [ ] Wave64 interpreter for the scalar/vector/memory subset; ISA calibration against the GPU.

## P5 — Machine model calibration
- [ ] Microbenchmarks (hand-written `mir`): latency/throughput per instruction class, MFMA issue/latency, LDS bandwidth and bank conflicts, global load latency.
- [ ] `measured` fields in `gfx950.yaml` regenerated by a script; tests check presence and sanity.

## P6 — Backend passes on `mir`
- [ ] Dependency DAG and list scheduler on the machine model.
- [ ] Waitcnt insertion/minimization (rebuild waits after scheduling).
- [ ] Hazard insertion (`s_nop`).
- [ ] Register allocation: deallocate physical → virtual (liveness), reallocate with tuple alignment and occupancy targets.
- [ ] Peepholes; kernarg preload.
- [ ] Default policy: import → pass pipelines → static check → battery → paired bench; keep the fastest verified.

Exit: default policy ≥ 1.0× amdclang geomean on the corpus, with paired wins reported.

## P7 — Agent interface
- [ ] Content-addressed store, states, traces, branches, tags.
- [ ] Session with action menu, legible rejections, `edit_ir`, `asm_diff`, `static_check`, `check`, `bench`, `profile`.
- [ ] MCP server + `agc` skill; CLI `agc run`.
- [ ] Profiler: `rocprofv3` counters and kernel trace in a worker job.

## P8 — High-level inputs and generators
- [ ] `tair`: elementwise/rowwise/reduction/contraction spec, text format, einsum, NumPy interpreter.
- [ ] Virtual-`mir` builder API and register allocator for generated code.
- [ ] Generators: elementwise (vectorized `dwordx4`), rowwise reductions (DPP/LDS), softmax, layernorm/rmsnorm.
- [ ] Manifests with no kernel source compile end to end.

## P9 — GEMM on MFMA
- [ ] MFMA operand/accumulator layouts in arch data; bf16/fp16 GEMM generator with LDS tiles, swizzles, pipelining.
- [ ] Direct-to-LDS loads, AGPR accumulators, wave ping-pong, XCD-aware remap (as measured wins).
- [ ] FP8 GEMM.
- [ ] Baselines: amdclang naive/tiled HIP, hipBLASLt.

## P10 — Attention
- [ ] Prefill (causal/non-causal) and decode generators with online softmax on MFMA.
- [ ] Baselines: amdclang HIP attention; library attention where available.

## P11 — Agent campaigns and self-improvement
- [ ] Agent sessions on corpus kernels with traces; paired wins reported.
- [ ] Trace database, retrieval, recipe promotion, knowledge notes.
- [ ] Final report: per-kernel speedups vs amdclang and libraries.
